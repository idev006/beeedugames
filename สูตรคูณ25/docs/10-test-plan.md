# Test Plan

## Unit tests

- ตรวจช่วงแม่คูณ 2–25 และตัวคูณ 1–12
- สุ่มสถานการณ์แล้วต้องมี learning target ถูกต้อง
- ประเมินกลุ่มที่ขาด/เกินและ feedback
- mastery update ไม่เพิ่มเมื่อผิด
- mission completion เปลี่ยน state ได้จริง
- vertical slice `7 × 2` เริ่มด้วย 7 กลุ่ม กลุ่มละ 2
- submit คำตอบก่อนสร้างกลุ่มและดู transformation ครบต้องถูกปฏิเสธ
- chargeGroup ไม่เพิ่มซ้ำเมื่อแตะกลุ่มเดิม
- โจทย์ใหม่/ยังไม่แม่นต้องเริ่มที่ grouping; โจทย์ที่ผ่านเกณฑ์ mastery จึงเริ่มที่ answering ได้
- ครบทุกกลุ่มต้องเข้าสู่ transforming และอนุญาตคำตอบเมื่อ animation เสร็จเท่านั้น
- ตอบผิดใน fast track ต้องกลับไป grouping ด้วยโจทย์เดิม

## Integration tests

- ทุกคู่แม่ 2–25 และตัวคูณ 1–12 ต้องสร้าง representation ที่ผลรวมตรงและมีไม่เกิน 12 กลุ่ม
- `17 × 6` ต้องแสดง 6 กลุ่ม กลุ่มละ `10 + 7` และสรุป `(6 × 10) + (6 × 7)`
- `25 × 12` ต้องแสดง 12 กลุ่ม กลุ่มละ `10 + 10 + 5` และสรุปว่า `4 × 25 = 100` ได้ 3 ชุดร้อย
- แม่มากกว่า 12 ต้องใช้ตัวคูณเป็นจำนวนกลุ่มผ่านสมบัติการสลับที่ โดยห้ามเปลี่ยนคำตอบจริง

- Home เลือกเขตแล้ว config ที่เข้า Game ตรงกับเขต
- กดผิดลดผลเฉพาะที่กำหนดและยังเล่นต่อได้
- เล่นจนจบชุดแล้วโหลดชุดใหม่หรือแสดงผลลัพธ์
- ซ่อมครบ milestone แล้วต้องประกาศก่อนเปลี่ยนเขต แสดงชื่อและบทบาทสมาชิกใหม่ถูกคน
- ระหว่าง milestone เวลาต้องไม่ลดและ mouse, touch, AR ต้องส่งคำตอบซ้ำไม่ได้
- หลังจบ milestone ต้องเปลี่ยนฉาก ตัวละคร และโจทย์เพียงครั้งเดียว
- กดเล่นใหม่ระหว่าง/หลัง milestone ต้องไม่มี timeout จาก session เก่ามาสร้างรอบซ้ำ
- หมดเวลา, pause, retry, quit ไม่ทำให้ session ค้าง
- ปิดเสียง/ลด motion แล้วทุก scene เคารพ settings
- ภารกิจ `7 × 2`: group-building → group-complete → answer verification → reward
- ตอบผิดหลังสร้างกลุ่มแล้วต้องคงภาพกลุ่มไว้เพื่อย้อนตรวจสอบ

## Visual and interaction tests

- ฉากไม่ถูก crop จนตัดจุดเล่น
- ตัวละครที่หันขวาอยู่ฝั่งซ้ายและสายตานำเข้าสู่พื้นที่เล่นโดยไม่ทับแท่น
- ตัวละครสลับ idle frames และตอบสนองเมื่อชาร์จกลุ่ม/ตอบถูก/ตอบผิด
- Pix, Maru และ Zen ต้องถูกตัดจาก source grid 6×2 แล้ว map เป็น runtime 7×2 โดยไม่มีภาพข้ามช่องหรือขอบตัวละครถูกตัด
- Canvas ไม่แสดงแถบคำสั่งซ้ำกับ side HUD; แถวแท่นและแผงเหตุผลต้องใช้พื้นที่ส่วนบนอย่างกระชับ
- side HUD ไม่บัง hit target
- sprite ไม่มีพื้นหลังดำหรือกรอบเกิน
- touch target อย่างน้อย 44px
- คลิกด้วย mouse ได้ทั่วพื้นที่วงกลมของตัวเลือก ไม่ใช่เฉพาะตรงกลาง
- mouse และ touch มี cursor/press feedback ก่อนส่งคำตอบ
- mouse, touch และ AR ส่งคำตอบผ่าน `GameStore.submit` เส้นทางเดียวกัน
- AR pointer ปรากฏเฉพาะเมื่อตรวจพบนิ้ว และ dwell เฉพาะตัวเลือกที่ pointer อยู่ภายใน
- AR ต้องเปลี่ยนเป้าหมายอัตโนมัติตาม phase โดยไม่ต้องปิด/เปิด AR ใหม่
- กลุ่มที่ชาร์จแล้วต้องไม่รับ dwell ซ้ำ และกลุ่มที่ซ่อนแบบ batch ต้องชาร์จได้ทั้ง Mouse/Touch/AR
- Answer Core ต้องมองเห็นได้ตั้งแต่ grouping ในสถานะล็อกพร้อมข้อความ `ล็อก • เติมให้ครบ`; ต้องไม่รับ Mouse, Touch หรือ AR จนเข้า answering
- เล่นแนวตั้ง/แนวนอนและจอแคบได้
- กลุ่มพลังงาน 7 กลุ่มอ่านได้ชัดว่าแต่ละกลุ่มมี 2 ดวง
- array model ต้องใช้วัตถุจุดชุดเดียว เคลื่อนจาก 7 กลุ่ม กลุ่มละ 2 ไปเป็น 2 กลุ่ม กลุ่มละ 7 โดยจำนวนรวมเท่าเดิม
- ก่อนตอบต้องไม่เปิดเผยผลรวม และหลังตอบถูกต้องสรุป `7 × 2 = 2 × 7 = 14`
- แบบจำลองการสลับที่ต้องไม่บัง Choices, ตัวละคร หรือพื้นที่กล้อง AR
- answer core ต้องเท่ากันทั้งขนาด สี texture aura และความเร็ว animation เพื่อไม่ชี้นำคำตอบ
- group state empty/charged/complete แยกได้โดยไม่พึ่งสีอย่างเดียว

## Performance

- initial load มี loading state
- asset แยกโหลดตามเขต
- ไม่สร้าง object จำนวนมากทุก frame โดยไม่จำเป็น
- animation และ particle มี reduced-motion fallback

## Playtest protocol

สังเกตโดยไม่ช่วยทันที: เด็กเข้าใจภารกิจจากภาพหรือไม่, รู้ว่าต้องจัดกลุ่มอย่างไรหรือไม่, ผิดแล้วรู้วิธีแก้หรือไม่, สนุกพอที่จะเลือกภารกิจต่อหรือไม่ แล้วเก็บคำพูด/จุดลังเลจริงเพื่อปรับ UX
